# 봉사단 운영 코파일럿 **WFK SafeBrief** — 설계 문서(Spec)

> 제품명: **WFK SafeBrief** = **Safe**(안전 인텔리전스) + **Brief**(파견 교육 브리핑). WFK = World Friends Korea.

- **작성일**: 2026-06-12
- **상태**: 설계 확정, 빌드 직전 (안전 기둥은 테스트 단계에서 추가·개선 예정)
- **공모전**: 2026 KOICA 공공데이터·AI 활용 챌린지 — 제출 마감 **2026-06-16** (참가신청서 + 아이디어 기획서 + 개인정보 동의서 → data@koica.go.kr)
- **빌드 접근법**: B 포커스형 (신규 단독 앱) + 기존 ODA Brief 백엔드 차용

---

## 1. 한 줄 정의

> **KOICA 공공데이터로 국가별 안전 리스크를 모니터링하고 파견 교육자료를 자동 생성·갱신해, 봉사단 운영인력(코디네이터 314명)의 '조사·분석·보고' 반복업무를 덜어 중도귀국·매몰비용을 줄이는 해외봉사단 운영 코파일럿**

두 개의 **동등한 기둥**으로 구성:
- **기둥 A — 안전 인텔리전스**: 공식 정보 ↔ 단원 체감의 갭을 탐지해 사고 전 경보 + 대처 가이드
- **기둥 B — 교육 브리핑 에이전트**: 작년 교육자료(PPT/Word)를 넣으면 신규 데이터와 비교해 변경점을 반영한 갱신본을 출력

---

## 2. 문제 정의 (배경)

- **규모**: 연 신규 파견 ~1,000명 / 활동 ~1,400명(35~46개국) / 누적 ~2.5만 명
- **운영 인력 급증**: 코디네이터(현지 안전관리·운영 담당) **180명(2023) → 240명(2024) → 314명(2025), +74%**. 47개 해외사무소.
- **매몰비용 구조**: 1인당 양성비용 ~1,975만원이 **환수 불가**(출국준비금·교육비·항공비). 중도귀국 127명(2020~), 자격박탈 11명에 2.2억.
- **운영 업무의 본질**: 코디네이터 직무기술서 6개 직무 전부의 필요기술에 **"정보 조사·분석·가공"** + **"보고서 작성"**이 공통으로 명시됨. 구체 task로 "수원국 법/제도/정책 여건 조사", "위험요인 조사·모니터링", "안전질병관리", "현지적응훈련 계획수립·교육제공"이 존재 → **LLM/RAG가 가장 잘하는 반복업무**.

→ 즉 운영·안전관리 인력이 매년 급증하고, 그들의 핵심 반복업무가 "조사·분석·보고"인데, 이를 AI가 덜면 **직접적 비용 절감**으로 이어진다.

## 3. 차별화 (경쟁 지형)

| 작품 | 연도 | 관점 | 우리와 겹침 |
|------|------|------|------------|
| 웨얼왓 (우수상) | 2024 | 예비단원 국가·직종 추천 | 지원자측 → ✗ |
| GROW (우수상) | 2025 | 해외봉사 맞춤정보·커리어 | 지원자측 → ✗ |
| 박지혜 인사이트허브 (사례작) | 2025 | ODA 성과·예산·리스크 대시보드 | ODA 일반, 봉사단 특화 아님 → 부분 |
| 내부 데이터경진 최우수상 | 2025 | 봉사단 **모집인원** 최적화 | 모집 단계 → ✗ |

→ **화이트스페이스 = "운영자(코디네이터·교육원) 관점의 봉사단 운영 효율화"**. 봉사단 수상작은 전부 지원자측, 내부 사례는 모집인원. 우리는 **파견 후 운영(안전·교육)** 영역으로 비어 있음.

**시그니처 차별 능력 (단순 조회·챗봇이 구조적으로 못 하는 것)**:
1. **갭 탐지** — 공식 안전정보 vs 단원 자가체감의 불일치 정량화
2. **연도 diff** — 작년 산출물 대비 "무엇이 바뀌었는지"만 추출
3. **출처 각주** — 생성물 전체에 [출처:refId], 할루시네이션 방어

## 5. 제품 구성 — 두 기둥

### 기둥 A — 안전 인텔리전스 (전부 국가 단위, 데이터 검증 완료)

| # | 컴포넌트 | 동작 | 데이터 |
|---|----------|------|--------|
| **A1** | **갭 스코어 랭킹** (이상탐지·급변 흡수) | 35개국을 공식정보↔체감 갭 크기로 정렬 → 정보 사각지대 우선순위 | 현지안전정보 API + 자가안전체감도 |
| **A2** | **추세 선행지표 경보** | `안전상황변화수준` 악화율이 임계 초과한 국가를 월별 자동 플래그 (절대수준이 "안전"이어도 변화율로 선제 경보) | 자가안전체감도 (월별 시계열) |
| **A3** | **자동 리스크 트리아지** | 현지안전정보 `cn`(서술형)을 LLM이 적재 시 {유형·심각도·요약}으로 자동 정형화 → 대시보드 카드. 각 카드에 "왜 떴어?" 드릴다운(보조 Q&A). **챗봇 아님 — 능동 표면화** | 현지안전정보 `cn` |
| **A4** | **대처 플레이북** | 긴급상황 대처요령·비상연락망·의료후송·질병별 대응을 즉시 제공. **현지안전정보 API에 국가별 실데이터로 존재**(긴급대처요령/치안·풍토병/의료지원) → 실데이터 기반, 출처 각주 | 현지안전정보 API(15099207) `cn` |

### 기둥 B — 교육 브리핑 에이전트 (전부 국가 × 직종 단위, 데이터 검증 완료)

| # | 컴포넌트 | 동작 | 데이터 |
|---|----------|------|--------|
| **B1** | **종합 파견 브리핑 생성** | 국가×직종 선택 → 직무·과거활동·문화·안전·일정을 한 보고서로 자동 조립 (출처 각주) | 파견직종 필수자격 + 현장사업목록 + 외교부 개황 + 현지안전정보 |
| **B2** | **교육자료 diff 에이전트** (시그니처) | 작년 PPT/Word 업로드 → pptx/docx 파싱 → 신규 코퍼스와 대조 → **변경점 추출**(정책·안전경보·직종 필수자격 변경) → **갱신본 PPT/Word 출력** | python-pptx/docx + 코퍼스 |
| **B3** | **출처·편집·내보내기** | 생성물 편집 + 근거 담기(바구니) + [출처:refId] 각주 + .md/.doc/.pptx 내보내기 (ODA Brief 보고서·바구니 재사용) | — |

**B1 콘텐츠 범주** (국가 × 직종):
- 그 나라에서 하게 될 일/직무 — 파견직종 필수자격 + 현장사업목록
- 과거 활동 이력 — 현장사업목록(사업명·활동종류·수혜자수·예산)
- 문화·전통·가치관·종교·민족 — 외교부 국가개황(코어) + 현지안전정보 생활·do&don't + 봉사활동 안내서(인용·링크)
- 안전·주의사항 — 현지안전정보 + 자가안전체감도
- 일정 — 모집·파견 일정 (보강)

## 8. 데이터 흐름

1. **적재**: ingest 스크립트 → 신규 어댑터로 정형 적재 + 임베딩 (A3 트리아지는 적재 시 LLM 태깅)
2. **안전**: 국가 선택 → 공식(현지안전정보·외교부) + 체감(자가체감) 조회 → 갭 스코어·추세 산출 → 카드/랭킹 + 플레이북
3. **교육**: 작년 PPT/Word 업로드 → 파싱 → 코퍼스 대조 → 변경점 추출 → 갱신본 생성·출력
4. 모든 생성물에 [출처:refId] 각주

## 9. 에러 / Graceful Degradation

- 안전정보 API 실패/키 미발급 → 캐시 폴백 (ODA Brief 3단 degrade 재사용) + "라이브 미연결" 표기
- 데이터 빈 국가 → graceful 안내 + 가용 데이터만 표시
- PPT/Word 파싱 실패 → 텍스트 추출 폴백 + 사용자 경고
- 생성물은 항상 출처 각주 (근거 없으면 "데이터 없음" 명시, 추정 금지)

## 10. 디자인 시스템

- **표준**: KRDS(범정부 통합 디자인시스템) 준수
- **색상**: KRDS 파랑 주색 + **KOICA Blue** 액센트 + 리스크 의미색(적·주·황·녹). (KOICA Blue 정확값은 VI 패키지로 확정)
- **서체**: Pretendard GOV (한/영), body 17px, line-height 150%+
- **타입스케일**: Display 36–60 / Heading 15–40 / Body 13–19px
- **접근성**: WCAG AA(4.5:1) 최소
- **무드**: 절제·신뢰·데이터 중심의 공공 실무 도구 (화려한 효과 금지)
- **제작 흐름**: design-shotgun으로 위 제약을 브리프에 주입해 시안 비교 → 선택 → (빌드 단계) Fable 5로 전환해 프런트 구현
